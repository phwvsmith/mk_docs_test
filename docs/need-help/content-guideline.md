# Content Guidelines

This page explains how to write and organise content to keep the site clear, consistent, and easy to use.

You don’t need technical knowledge—just follow these simple rules.

---

## 🎯 Purpose of This Site

This site is a **shared knowledge base**.

✅ Anyone can contribute  
✅ Content should be easy to read and understand  
✅ Information should be accurate and up to date  

---

## 🧱 Page Structure

Every page should follow a simple structure:

# Page Title

## Overview

Briefly explain what the page is about.

## Main Content

Break into clear sections using headings.

## Example (optional)

Add examples where useful.

## Notes (optional)

Any additional useful information.

---

## 📝 Writing Style

### ✅ Keep it simple
- Use plain language
- Avoid jargon where possible

### ✅ Be clear and direct
- Write short sentences
- Get to the point quickly

### ✅ Be consistent
- Use similar wording across pages
- Follow existing patterns

---

## 📌 When to Create vs Edit a Page

### ✅ Edit an existing page if:
- The information already exists
- You are improving or updating content

### ✅ Create a new page if:
- The topic is new
- The content would make an existing page too long

---

## 🧭 Page Naming

Choose clear and descriptive titles.

✅ Good examples:
- Data Access Guide
- How to Request Access
- Pipeline Overview

❌ Avoid:
- Generic names like "Notes" or "Stuff"
- Very long or unclear titles

---

## 🧩 Content Organisation

### ✅ Use headings

Break content into sections:

## Overview  
## Steps  
## Examples  

---

### ✅ Use lists

Instead of long paragraphs:

- Step 1
- Step 2
- Step 3

---

### ✅ Keep sections short

- Avoid large blocks of text
- Split content into smaller sections

---

## 👥 Audience Awareness

Write for your audience:

- Analysts  
- Scientists  
- Engineers  

✅ Assume basic knowledge  
❌ Don’t assume deep technical expertise  

---

## 🔗 Linking Content

### ✅ Link related pages

Help users navigate easily:

- Link to relevant guides
- Avoid duplication

---

## 🖼️ Images and Diagrams

Use visuals when helpful:

✅ Use images to explain complex steps  
✅ Keep file names simple and descriptive  
✅ Store images in the correct location  

---

## 🔄 Updating Content

✅ Keep pages up to date  
✅ Fix outdated or incorrect information  
✅ Improve clarity when needed  

---

## ⚠️ Avoid These Common Issues

❌ Very long paragraphs  
❌ Duplicate content across pages  
❌ Unclear or vague explanations  
❌ Overly technical language  
❌ Missing structure  

---

## ✅ Good Example

## Overview
This page explains how to request access to a dataset.

## Steps
1. Submit a request form  
2. Wait for approval  
3. Access the dataset  

## Notes
Contact the data team if you have issues.

---

## ❌ Bad Example

- No headings  
- Long paragraph with no structure  
- Unclear instructions  

---

## ✅ Quick Checklist Before Saving

- Is the title clear?  
- Is the content easy to read?  
- Are headings used properly?  
- Are there unnecessary duplicates?  
- Would someone new understand this?  

---

## 💡 Tip

If you’re unsure, keep it simple and follow the structure used in other pages.  
Consistency is more important than perfection.
